# Планировщик задач (итоговый проект, Go)

Веб‑приложение: статический фронтенд, REST API и SQLite. Задачи имеют дату, заголовок, комментарий и опциональное правило повторения (`repeat`). Поддерживаются одноразовые и периодические задачи, отметка выполнения (со сдвигом даты по правилу) и удаление.

---

## Соответствие этапам технического задания

| Этап | Что сделано |
|------|-------------|
| 1. Веб‑сервер | Статика из каталога `web/`, порт по умолчанию `7540` (`TODO_PORT`) |
| 2. БД | SQLite, таблица `scheduler` (колонки `id`, `date`, `title`, `comment`, `repeat`), индекс по `date`; файл БД: `TODO_DBFILE` или `scheduler.db` |
| 3. `NextDate` | Реализация базовых правил `d` и `y` (см. «звёздочки» для расширенных) |
| 4. Добавление | `POST /api/task` |
| 5. Список | `GET /api/tasks` (сортировка по дате, лимит записей) |
| 6. Одна задача и правка | `GET /api/task?id=…`, `PUT /api/task` |
| 7. Выполнение и удаление | `POST /api/task/done?id=…`, `DELETE /api/task?id=…` |
| 8. Вспомогательно | `GET /api/nextdate?…` (для проверок и фронтенда) |
| 9. Аутентификация (опционально) | `POST /api/signin`, JWT в cookie `token` при `TODO_PASSWORD` |
| 10. Docker (опционально) | `Dockerfile` в корне репозитория |

### Реализованные эндпоинты (кратко)

| Метод | Путь | Назначение |
|--------|------|------------|
| `GET` | `/` | Главная (статика) |
| `GET` | `/api/nextdate` | Следующая дата по правилу (query: `now`, `date`, `repeat`) |
| `POST` | `/api/signin` | Вход: JSON `{"password":"…"}`, ответ `{"token":"…"}` или `{"error":"…"}` |
| `POST` | `/api/task` | Создать задачу |
| `GET` | `/api/task?id=…` | Задача по id |
| `PUT` | `/api/task` | Обновить задачу (JSON с `id`) |
| `DELETE` | `/api/task?id=…` | Удалить задачу |
| `GET` | `/api/tasks` | Список ближайших задач |
| `POST` | `/api/task/done?id=…` | Выполнить (одноразовая — удаление, периодическая — сдвиг даты) |

Если задан `TODO_PASSWORD`, к запросам к **задачам** (все методы `/api/task`, `GET /api/tasks`, `POST /api/task/done`) нужна валидная cookie `token`. `/api/nextdate` и раздача статики (включая `/login.html`) не требуют авторизации.

## Локальный запуск

1. Установите Go (версия не ниже указанной в `go.mod`).
2. В корне репозитория:
   ```bash
   go run .
   ```
3. В браузере: **http://localhost:7540/** (главная) или **http://localhost:7540/login.html** (если включён пароль).

### Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `TODO_PORT` | Порт HTTP (по умолчанию `7540`). Должен **совпадать** с полем `Port` в `tests/settings.go`, иначе тесты уйдут на другой порт. |
| `TODO_DBFILE` | Путь к файлу SQLite. Если не задан — используется `scheduler.db` в текущем рабочем каталоге при запуске. |
| `TODO_PASSWORD` | Непустая строка — включает проверку cookie `token` (JWT) для защищённых API. |

### Аутентификация

1. Задайте, например: `set TODO_PASSWORD=секрет` (cmd) или `$env:TODO_PASSWORD="секрет"` (PowerShell).
2. Зайдите на `/login.html`, введите пароль — фронтенд вызовет `POST /api/signin` и установит cookie.
3. **Запуск автотестов с паролем:** получите `token` из JSON ответа `/api/signin` и вставьте его в **`Token`** в `tests/settings.go` (как в материалах курса). Параллельно задайте серверу тот же `TODO_PASSWORD` и порт, что в `Port`.

## Запуск тестов

Тесты из пакета `tests` **не поднимают сервер сами** — сначала нужно запустить приложение, затем в **другом** терминале:

```bash
go test ./tests
```

**Обязательно:**

- Сервер и `go test` используют **один и тот же порт** (через `TODO_PORT` и `Port` в `tests/settings.go`).
- Файл базы, с которым работает сервер, должен быть доступен пути из теста: в `settings.go` по умолчанию `DBFile = "../scheduler.db"` — это файл в **корне репозитория**, если `go test` запускается из корня (родительская папка для пакета `tests` — корень проекта).

**Пример (PowerShell, два шага):**

```powershell
# Терминал 1
$env:TODO_PORT=7540; go run .

# Терминал 2 (тот же порт)
$env:TODO_PORT=7540; go test ./tests
```

Проверка отдельных сценариев (сервер должен быть запущен):

```bash
go test -run ^TestApp$       ./tests
go test -run ^TestDB$        ./tests
go test -run ^TestNextDate$  ./tests
go test -run ^TestAddTask$   ./tests
go test -run ^TestTasks$     ./tests
go test -run ^TestTask$      ./tests
go test -run ^TestEditTask$  ./tests
go test -run ^TestDone$      ./tests
go test -run ^TestDelTask$   ./tests
```

## Docker

Сборка:

```bash
docker build -t todo-scheduler .
```

Пример запуска (Windows **cmd**, перенос строки `^`):

```cmd
docker run --rm -p 7540:7540 ^
  -e TODO_PORT=7540 ^
  -e TODO_DBFILE=/data/scheduler.db ^
  -e TODO_PASSWORD=secret ^
  -v C:\path\to\data:/data ^
  todo-scheduler
```

В PowerShell вместо `^` — обратная кавычка `` ` `` в конце строки или одна длинная строка. Каталог на хосте `C:\path\to\data` должен существовать и быть доступен для записи, чтобы создался файл БД. Откройте **http://localhost:7540/**.

## Структура репозитория (основное)

- `main.go` — точка входа, БД, регистрация маршрутов и статики.
- `pkg/api/` — обработчики API, `NextDate`, аутентификация.
- `pkg/db/` — инициализация схемы, работа с таблицей `scheduler`.
- `web/` — фронтенд (статика).
- `tests/` — интеграционные тесты курса; настройки — `tests/settings.go`.
